# Plan: apply the member's source-check result (ai-tools-alerts#tavj)

Spec: `docs/superpowers/specs/2026-11-25-tavj-apply-source-check-result-design.md` (as amended after its review). One branch, four chunks, in this order. Every chunk ends with `python3 -m pytest -q tests/<the files it names>`; the whole gate runs once at the end, in a clone that holds only this branch.

## Chunk 1: the reader (`aitools_alerts/pull.py`, `aitools_alerts/state.py`)

- [ ] `state.py`: `State.lowerings: dict` (reply id -> checkpoint time), `State.refused: set` (root ids), `State.interrupts: dict` (bucket -> {root id: local time}), `State.reset_at: int | None`, `State.unverified_damaged: bool`. Read from `unverified.json` in `State.load` by `_load_unverified` (missing: empty; unreadable or another shape: `unverified_damaged`, never `StateError`), refreshed in `locked()`, written by `save_unverified()`, which clears the flag. Shape: exactly the keys `lowerings`, `refused`, `interrupts`, `reset_at`; every id 64 lowercase hex; every time an integer in 0..2^53; at most `MAX_UNVERIFIED_ENTRIES = 20000` entries per record, which is `pull.MAX_STORED_EVENTS`: every entry is keyed by a stored event or stands for one stored root, so no record the CLI writes is refused on reading (a test holds the two constants equal and reads back 6000 entries).
- [ ] In the same chunk, so that no test between chunks calls a check with the wrong arguments: every caller of a check passes `stated`. `cli._lowering_check` returns `_Check(cache, rs, pin)`, callable `(adv, level, stated=())` -> `verify.lowering`, with `.whole(...)` -> `verify.lowering(..., whole=True) is True` (the `stated`, `pin` and `whole` parameters of `verify.lowering` are added here and ignored until chunk 2); `cmd_verify` passes `t.stated`; the `says` helper of `tests/test_curator_hold.py` takes a third argument.
- [ ] `pull.py` `Thread`: `offered_by: str | None`, `stated: tuple`, `waiting: str | None` (set by `standing`: the level of a relay-bot lowering the check did not settle and that is not yet applied).
- [ ] `_Hold.offered_by`. `_bot_reply`: a level-only lowering sets `offered_by` to the reply's id unless the same level is already offered by a relay-bot reply; a block that names a level and applies clears it with `offered`. Every curator path that sets `offered` clears `offered_by`.
- [ ] `threads_from`: collect `stated` for a relay-bot thread: the root `(level, wire.claim_of(root))`; each relay-bot reply whose block names a level `(level, wire.claim_of(reply))`; each curator `level:` line or block level that applies `(level, None)`.
- [ ] `UNCHECKED_LOWERING_S = 72 * 3600`. `standing(t, now, check, since=None)`: `check` is called `check(widest(t), level, t.stated)`. After the hold branch: True applies; None applies when `_stood(t, now, since)`: `offered_by` set, `offered` a level, `now` not None, `since[offered_by]` an integer with `now - it >= UNCHECKED_LOWERING_S`; otherwise the widest state, with `waiting=t.offered` when the answer was None and `offered_by` is set.
- [ ] `active(..., since=None)`: drops the entries of `since` whose reply `listed` does not hold, then passes it on. `offers(threads, held, now, listed) -> dict`: for each thread whose root and `offered_by` are both in `listed` and whose `offered` is a level, `min(held.get(id, now), now)`; nothing else. `now` or `listed` None: `held` unchanged.
- [ ] Tests, `tests/test_unchecked_lowering.py` (reader part): the offer id survives a repeat and moves with a new level; a curator's offer has none; 72 hours by the clock given, not before, never with `since` None, never for a retraction, never when the check says False; `offers` adds, keeps the earlier time, drops what is no longer listed or offered; `stated` has the root's and each level reply's claim; the state record's shape, a damaged one, a missing one.
- Acceptance: `tests/test_curator_hold.py`, `tests/test_pull.py`, `tests/test_expiry.py`, `tests/test_bot_patch.py` pass with only the `says` helper taking a third argument.

## Chunk 2: the member check (`aitools_alerts/verify.py`)

- [ ] `VERSION = 3`; `_WHYS[CONFIRMED] = ("match", "withdrawn")`. `judge`: at `notice`, complete, every source an authority, `s == NONE` and `named`: `CONFIRMED, "withdrawn"`, before the `unsupported` return.
- [ ] `Asked(Advisory)` with `claimed: bool = False`; `at_level(adv, level, claimed=False)` builds it. `_Target.claimed`; in the key only when True (the keys of today's states do not change).
- [ ] `claimed(adv, level, stated, rs=None, pin=None) -> bool` as the spec defines it; False for no `stated`, an id `norm_id` refuses, any exception.
- [ ] `_Run.thread`: for a claimed target whose first id is a CVE and whose catalog record does not list it (`not first["lowers"] and not first["support"]`), judge with a copy of that record marked an authority. For a CVE first id, the listed aliases are read in descending order of `weight`: the highest rank the stored record of the alias gives a product of the thread, 0 when the record is missing, no authority or does not name the CVE (a stable sort: equal weights keep the thread's order).
- [ ] `lowering(adv, level, cache, now, rs=None, stated=None, pin=None, *, whole=False)`: `asked = at_level(adv, level, claimed(...))`; False on any `below-source`; None unless fresh, `level` a level, and every why in `{"match", "withdrawn", "reading", "unsupported"}`; then True when `whole`, or `level` is at or above `reading_cap`, or the state is claimed.
- [ ] Tests in `tests/test_unchecked_lowering.py` (check part): withdrawn at notice is confirmed, silent-about-the-product is still unsupported; a claimed lowering to notice confirms on a withdrawn advisory and on fields that give notice; unclaimed, a claim with another id, a claim the ruleset computes differently, a multi-product thread with a claim for one, a later unclaimed level statement: None; a delisted CVE: None unclaimed, True claimed, False when an alias supports more; critical to high with fields that give notice: True without a claim; a retraction: never True; the supporting alias is read first when three others are put before it.
- Acceptance: `tests/test_verify.py`, `tests/test_verify_cli.py`, `tests/test_curator_hold_cli.py` pass; an expectation there changes only where the spec changes the rule, and each such change is named in the run record.

## Chunk 3: the CLI (`aitools_alerts/cli.py`)

- [ ] `main`: `_mend(st)` after `State.load()` for every command that reads the feed: a damaged record is rewritten empty with `reset_at = now` under the lock (in memory only when the directory cannot be written), one line on stderr.
- [ ] `_Check` (chunk 1) now gets its answers from the chunk 2 rules; nothing to change here.
- [ ] `_matches`: `now, listed = pull.head_clock(st)`; `_note_offers(a, st, now, listed, check)`: `want = pull.offers(...)`; for each standing offer: False adds the thread's root id to `refused`, True or `.whole` removes it; the time of a refused thread's offer is set to `now`; root ids of threads that no longer exist are dropped; saved under the lock when changed. Returns None for a CLI too old or out of date, else the lowerings of threads not refused. `a.asked` is built with `_asked(a, st, t, level)`: `verify.at_level(widest, level, verify.claimed(widest, level, t.stated, None, pin))`.
- [ ] `Entry.waiting`; `_match_json` gains `lowering_waits`; `cmd_check` prints the waiting line for matched entries.
- [ ] `_interrupts(a, st, s, pairs) -> (pending, held, grants, loose)` over `_unseen_critical` (kept as it was): a curator's alert is pending; a relay-bot alert that is `_confirmed_now` takes the one slot of its `verify.state_key`; any other, or a confirmed one whose slot is taken, takes one of `MAX_UNVERIFIED = 2` of its poster key unless `reset_at` is inside the window; an alert already holding a slot in the bucket is pending with no new grant; the rest are held. Pure: nothing is written.
- [ ] `_reserve(st, pending, held, grants) -> (pending, held)`: under the lock, against the record as it is then, records each grant whose bucket still has room, drops slots outside the window, saves; an alert whose bucket filled meanwhile moves from pending to held. A directory that cannot be written grants for this command. `cmd_run` and `cmd_notify` call it before anything is printed, returned or sent, and take the JSON (`unseen_critical`, `held_critical`), the exit status and what is sent from its result; the late pass of `cmd_run` does the same.
- [ ] `_notify(st, s, pending, loose=frozenset())`: as before, and the text of an alert whose root is in `loose` gets a last line, `Not verified from this machine`, appended after `notify.format_text` has cut the text to its limit, so the line is never cut. `cmd_notify` goes through `_interrupts` and `_reserve`; the direct call in `tests/test_cli.py` keeps working with the default `loose`.
- [ ] `cmd_run`: `held_critical` in the JSON; after the source check, when `verify` is not off, `_interrupts` again and what is now pending and was not tried is sent. `_source_check` adds the critical matches to `recheck`. `cmd_check`: one line `not verified from this machine: <ids>` for relay-bot matches whose result is unknown, one line per held critical.
- [ ] Tests, `tests/test_unverified_cli.py`: the acceptance cases of the issue and success criteria 1 to 8 of the spec through `cli.main`; the mark on the notification of an unknown, a contradicted and a `verify = "off"` alert; three unverified criticals through the `notify` command; a slot a concurrent run took (the record changed between `_interrupts` and `_reserve`) is reported as held; a matching authority beside a record that is no authority still confirms, and the same record listing the CVE refuses.
- Acceptance: `python3 -m pytest -q tests` passes.
