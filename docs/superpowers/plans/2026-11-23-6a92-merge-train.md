# Plan: merge train (6a92)

Spec: docs/superpowers/specs/2026-11-23-6a92-merge-train-design.md

Every merge command, verbatim:

    gh pr merge <n> --merge --author-email 19930+Joi@users.noreply.github.com

followed by `git fetch origin && git log -1 --format=%ae origin/main`, which
must print `19930+Joi@users.noreply.github.com`. Anything else stops the train.
The tip of main can move between the merge and the fetch, so the final check
reads each PR's own merge commit: `git log -1 --format=%ae "$(gh pr view <n>
--json mergeCommit --jq .mergeCommit.oid)"`.

Pre-check before each merge: in a scratch worktree, `git merge --no-edit
origin/<branch>` onto the current `origin/main`, then `scripts/test-gate.sh`
there (no GIT_DIR or other GIT_* variable set; never from a hook). The
worktree is removed afterwards.

The history scan reads every ref in the clone, scratch worktrees included.
This clone holds local-only refs from an earlier restore that reach objects
already known to hit, and they were never pushed. So the pre-check runs with
`PUBLIC_SCAN_KNOWN` pointing at a private scratch copy of the known list
(mode 600, outside the repository). The copy adds only the object ids that
`scripts/public-scan.sh --hit-ids` reports and that no `origin` ref or tag
reaches. Any hit that a public ref reaches stays fatal.
